# AdSense 신청 준비 및 운영

## 구현된 공개 안내

- `/about`: 서비스 소개, 운영자 연락처, 비공식 팬사이트 안내
- `/guide`: 수동 입력, OCR, 이미지 생성, 로컬 저장과 클라우드 동기화 사용법
- `/guide/scoring`: 실제 계산 구현을 바탕으로 한 CV·AV 기준 및 한계
- `/privacy`: 처리 정보, 외부 서비스, 브라우저 저장, 광고 쿠키와 맞춤 광고 선택 방법
- `/terms`: 이용 조건, 광고와 권리 안내, 연락처

위 페이지는 인증 없이 접근할 수 있고 푸터에서 연결된다. 회원가입 팝업은 동일한 개인정보처리방침·이용약관 컴포넌트를 사용한다. 안내 페이지 직접 방문 시 자동 공지는 열리지 않는다. `robots.txt`와 `sitemap.xml`에도 공개 안내 경로를 제공한다. 사이트맵의 도메인은 기존 HTML의 `og:url`과 같은 `https://wuwa.dev`이며, 실제 대표 도메인이 달라지면 함께 갱신한다.

## 배포 및 신청 전 확인

1. 기존 `frontend/index.html`의 게시자 ID `ca-pub-3909722715571731`가 신청할 본인 계정의 ID와 일치하는지 AdSense에서 확인한다. 이 ID의 소유권이나 승인 여부는 저장소만으로 확인할 수 없다. 기존 연결 코드는 유지했고 광고 슬롯을 새로 활성화하지 않았다.
2. 실제 운영 설정과 공개 방침을 대조한다. 특히 제공자별 보관·삭제 기간, 이미지/로그 보관 설정, 개인정보 국외 처리 내역과 권리 요청 처리 절차는 운영자가 확인해야 한다. 문구 추가만으로 법적 적합성이나 Google 승인이 확정되지는 않는다.
3. 게임 이미지·데이터 및 이용자가 업로드하는 자료의 이용 조건과 광고를 통한 수익화 가능 범위를 확인한다. 비공식 팬사이트 표시는 이용 허락을 대신하지 않는다.
4. 변경을 운영 환경에 배포한 뒤 시크릿 창에서 위 다섯 주소를 직접 열고 새로고침한다. 약관, 연락처, 본문, 푸터 링크가 로그인 없이 보여야 한다.
5. `/robots.txt`와 `/sitemap.xml`이 실제 텍스트/XML로 제공되는지 확인한다. Vercel은 정적 파일을 SPA fallback보다 먼저 제공해야 한다. 로컬 확인만으로 운영 배포 상태가 확인되는 것은 아니다.

## AdSense에서 해야 할 작업

1. [계정 만들기](https://adsense.google.com/start/)에서 실제 사이트 주소를 등록한다.
2. 지급 정보와 계정 설정을 완료하고, 대시보드가 요구하면 본인 인증을 진행한다.
3. 사이트 소유권 확인 방식에 맞게 기존 코드의 ID와 연결 상태를 확인한다. Google이 지정한 작업을 마친 뒤 사이트 검토를 요청한다.
4. 자동 광고를 사용할지 대시보드에서 확인한다. 소량 게재가 목표라면 처음에는 자동 광고를 끄고, 승인 후 수동 광고 한 곳부터 시작하는 구성을 권한다. 원격 계정 설정은 이번 소스 수정으로 바뀌지 않는다.
5. EEA·영국·스위스 이용자에게 맞춤 광고를 제공할 때는 Google 인증 CMP를 설정한다. AdSense의 개인정보 보호 및 메시지 도구를 사용할 수 있다. 소스에 쿠키 안내 문구를 넣는 것만으로 동의 수집이 구현되지는 않는다.
6. AdSense가 안내하는 본인 게시자 ID의 `ads.txt` 행을 확인해 `frontend/public/ads.txt`로 배포한다. 이번 변경에는 소유권이 확인되지 않은 ID로 파일을 생성하지 않았다.

## 승인 후 소량 광고 도입

- 광고 단위를 생성한 뒤 발급된 광고 슬롯 ID로 구현한다. 슬롯 ID 없이 임의 값으로 광고 요청을 만들지 않는다.
- 홈이나 설명 콘텐츠 하단 등 이용자의 작업을 방해하지 않는 한 곳부터 시작한다. 편집 버튼·다운로드 버튼 근처에서 오클릭을 유도하지 않는다.
- 광고가 없을 때 과도한 빈 공간이 남지 않도록 하고, 로딩에 따른 화면 이동과 모바일 레이아웃을 점검한다.
- 자기 광고 클릭, 클릭 요청 문구 또는 인위적인 트래픽으로 검증하지 않는다.

## 로컬 검증 (2026-10-29)

- `npm run build` 통과. 기존의 큰 번들 및 `test.jpg` 경로 경고는 남아 있다.
- 공개 안내 5개 경로 HTTP 200, `robots.txt`는 `text/plain`, `sitemap.xml`은 `text/xml`로 응답.
- 브라우저에서 안내 페이지 직접 접근, 메뉴 이동, 자동 공지 미표시, 390px 모바일 줄바꿈·푸터 및 1280px 데스크톱 레이아웃 확인.
- 전체 TypeScript 검사에는 기존 오류 30개가 있다. 수정한 소스의 HEAD 원본을 메모리에서 복원한 진단과 비교했으며 새 진단은 0개였다.
